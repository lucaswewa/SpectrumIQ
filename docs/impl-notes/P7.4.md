# P7.4 — Live mosaic UI — implementation notes

- **Status:** Review
- **Branch / commits:** `phase/P7.4-mosaic-ui`, from `main` at `88236c4`
- **Date:** 2026-10-27

## Summary

- **The Mosaic page** (`/#/mosaic`, ADR-0060):
  - the live mosaic filling the main view, dragged to pan and zoomed with the wheel about the
    pointer, first showing what was painted, or else the stage;
  - the camera's field where the stage is, or a dot without a calibration;
  - a minimap of what was painted and the view within it, which a click recentres;
  - a double-click moves the stage there, within its travel;
  - Paint on or off, Show it all, Go to the stage, Clear once confirmed, Save told in a toast, and
    a status line with the frames painted and the pages' GPU memory.
- **`MosaicBackdrop`:** the `mosaic_live/view` stream through the stream budget, the map's view
  written as the viewport at most every 100 ms, and each image placed where the viewport the
  server last took puts it, so it moves with the view until the next arrives.
- **`mosaic/viewport.ts`:** a view's viewport, shrunk to fit 1920 × 1080 and its zoom within what
  the server renders; the stage box an image shows, and where it sits in a view. **`throttle.ts`:**
  once an interval, the last call always made.
- **The `mosaic` store:** `enabled`, `viewport`, `bounds` and `px_per_um` (read each second),
  `stats` (each 2 s); `setEnabled`, `setViewport` (throttled), `clear`, `save`.
- **The Scan page's stage map** draws over the mosaic once something was painted, its view the
  viewport, its travel and shapes on top.
- **`/#/dev/mosaic`:** the page against the fake instrument, whose `fakeMosaic.ts` paints a field
  wherever its stage stands still and renders the viewport as the server does.

## Interfaces

- **Web:** `useMosaicStore`; `MosaicPage`, `MosaicBackdrop`; `mosaic/viewport`'s `viewportOf`,
  `covered`, `placement`, `shownBy`, `union`, `MAX_SIZE`, `ZOOMS`; `mosaic/throttle`'s `throttle`.
- **Server:** none changed.
- **For M8:** the stage map's region is drawn over what was imaged; the stitched result has its
  own viewer.

## Deviations

1. **The image is placed by the last viewport the server took,** not by a viewport carried in
   each image: the one image rendered while the viewport changed may sit a step off, until the
   next (ADR-0060).
2. **One viewport per server,** the last writer winning: two clients looking at once see each
   other's views.
3. **The stage map turns dark** where nothing was painted, once anything was: the server renders
   unpainted stage black.
4. **The fake mosaic paints when asked for its bounds** too, as the server paints whether or not
   anything looks.
