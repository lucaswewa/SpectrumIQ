# P9.4 — Frontend: login, roles, control token and admin — implementation notes

- **Status:** Review
- **Branch / commits:** `phase/P9.4-multi-client-ui`, from `main` at `596d5fa`
- **Date:** 2026-10-28

## Summary

- **The session** (`web/src/auth/`, ADR-0068):
  - a login page in front of the shell, only where the service enforces one (`me`'s 401 says so);
  - a 401 anywhere ends the session, and the login asks again;
  - the desktop logs in by itself, by the local console's secret, which the shell reads
    (`local_secret`) from the file the service names to this computer.
- **Controls disabled with the reason, never hidden:**
  - a control needs `process`, `operate` or `admin`, and `ControlPane need`, `GatedFields` or
    `useGate` disable it, saying why;
  - the Live, Mosaic, Scan, Calibration and Jobs pages, Stitch and the exports, Delete, and STOP
    for a viewer;
  - the first-run calibration prompt opens only for a session that holds the token.
- **The control token's bar** above every page: the holder and since when; Take control, Release,
  Take over; who is logged in, and Log out. The holder's heartbeat runs every 10 s.
- **The Admin page:**
  - the users, with a role to choose, a new password asked for in a dialog, and Remove asked
    first;
  - the audit trail, filtered by who and what, 25 to a page;
  - both on `AppDataTable`, TanStack Table's headless core styled with the tokens.
- **The service:**
  - the users over HTTP, an admin's (`users.rs`);
  - the local console's user made at start;
  - `GET /api/siq/auth/local` naming the secret's file to this computer;
  - a read recorded by its class, not its method;
  - passwords cut from the trail.
  - `config/sim.toml` now enforces.
- **The examples log in:** `examples/python/siq_session.py` uses `SIQ_USER` and `SIQ_PASSWORD`,
  and takes and keeps the token for the scripts that change the instrument. The dev page is
  `/#/dev/admin`.

  - `GET` and `POST /api/siq/users`, `PUT` and `DELETE /api/siq/users/{name}`, all classed admin;
  - `GET /api/siq/auth/local`, `{"file"}`, from loopback only;

- **Desktop:** the command `local_secret`, allowed to `remote` pages.
- **For P9.5:** the login form (Name, Password, Log in), the token bar (`aria-label="Control of
  the instrument"`) and its buttons, and the reasons' texts, for the end-to-end tests to drive.

## Deviations

1. **The users routes and the local user** were added to the service, outside the brief's web
   scope. The Admin page needs them, and the desktop's login needs a user it can log in as without
   anyone adding one.
2. **No `/login` route:** the login stands in front of the shell, so the URL asked for stays, and
   shows once logged in. That is the brief's "redirect".
3. **Found while checking by hand in Edge, and fixed:**
   - The calibration wizard welcomed a viewer: it now opens only for a session that may calibrate
     (ADR-0051, amended).
   - The wizard's "close early?" question opened beneath the wizard. The shell now mounts after
     the login, so after the question's portal. Alert dialogs have their own layer, `--z-alert`.
   - Each visit to Datasets by anyone was audited: a `POST` that reads is now told by its class
     (ADR-0067, amended).
   - The Admin page's Who filter queried on every keystroke: `v-model.lazy` does nothing on a
     component. It now applies at Enter or when leaving the field.
   - The page's title was smaller than its sections'.
4. **Found by the tests, and fixed:**
   - The token store dropped the token when the session's `me` was replaced before the holder was
     known: a watch with a shallow source runs on every trigger. A holder not yet known isn't
     evidence of a loss.
   - The session defaulted to enforced. Every page test ran as no one at all, unnoticed, since
     happy-dom doesn't disable a fieldset's buttons. It now starts off until the server says.
5. **STOP is disabled for a viewer**, who may not stop (ADR-0066). It stays enabled for everyone
   else whatever is moving (ADR-0039, amended).
6. **The CLI's first admin:** while there is no admin, a new user is one, since the service now
   makes the local console's user itself.
7. **Not gated:** keys and gestures on the image (the arrows, PgUp and PgDn, the wheel,
   double-click to move). Without the token the server refuses them, and the toast says why.
8. **The Admin page loads when first opened,** as a lazy route: with TanStack Table, it took the
   app's main chunk past Vite's 500 kB warning, for a page only admins open.
9. **Fixed on the way:** the web README's broken About row (P8.4), and the requirements table's
   extra empty cell in REQ-SEC-002 and REQ-SEC-003 (P9.2, P9.3).

- `crates/siq-config/tests/config.rs`: the `sim_toml` snapshot, now enforcing, with the console's

- **By hand, in Edge,** against the simulator with an admin, an operator and a viewer:
  - a wrong password refused;
  - the viewer's controls and STOP disabled with the reason, and no wizard;
  - the operator taking control, the wizard welcoming them, the controls coming on;
  - the viewer and the admin seeing who has control, Take over offered to the admin alone;
  - the admin's page with the users and 25 audit entries, a password changed in its dialog, a
    removal asked first, Who applied at Enter;
  - `/#/dev/admin`: each user's view, and the Live page's controls coming on with control;
  - `examples/python/live_and_move.py` with `SIQ_USER`, and a 401 without it;
  - no page errors.
