# P0.3a — Telemetry (`siq-telemetry`) — implementation notes

- **Status:** Review
- **Branch / commits:** `phase/P0.3a-telemetry`, from `main` at `a47f06a`
- **Date:** 2026-10-23

## Summary

- **`LogConfig` and `init`:**
  - the console, plus daily rolling `spectrumiq.YYYY-MM-DD.log` files through a non-blocking
    writer, keeping `keep_days` files;
  - the filter in `RUST_LOG` syntax, which the `RUST_LOG` variable overrides;
  - `init` creates the log folder.

  `LogConfig` serializes, with a JSON Schema, so P0.3b embeds it as `[log]`.
- **`Registry`:** named `Counter`, `Gauge` and `Histogram`. Each updates with one atomic operation,
  or one plus a compare-and-swap for a histogram's sum. Names are checked, and kind or bounds
  conflicts are errors. `snapshot()` serializes to JSON.
- **`cargo xtask loc`** now classifies insta `snapshots/` folders and `.snap` files as tests.

## Interfaces

- `siq_telemetry::{LogConfig, init, LogGuard, TelemetryError}`;
- `siq_telemetry::{Registry, Counter, Gauge, Histogram, MetricValue, MetricError}`;
- `metrics::Bucket`.

The metric naming convention, `<component>.<quantity>[_<unit>]`, and the snapshot's JSON form are
in ADR-0019. P2.4's `/api/siq/system/metrics` serves `Registry::snapshot()`.

## Deviations

1. **P0.3 was split into P0.3a (this phase) and P0.3b (`siq-config`).**
   - *Why:* the complete phase measured about 1060 counted lines against a budget below 1000, and
     an estimate of about 800. It was built whole first; simplifying the configuration's validation
     saved about 40 lines, but not enough.
   - *Why this split:* telemetry and configuration are independent crates. P0.3b depends on
     P0.3a's `LogConfig`.
   - *Plan changes:*
     - the M0 brief and the roadmap list both phases;
     - P2.3, P4.3 and P7.1 now depend on P0.3b, which depends on P0.3a;
     - the count is 87 phases.
2. **`TelemetryError::Folder`, beyond the brief.** `init` creates the log folder, because
   `tracing-appender` otherwise prints "Error reading the log directory" on a first run: it prunes
   old files before it makes the folder.
3. **`Histogram::record` uses a compare-and-swap loop.** `AtomicU64::fetch_update` is deprecated
   on the 1.99 toolchain, and its replacement `try_update` may not exist at the workspace's minimum
   Rust (1.98).
4. **The `loc` change** (2 counted lines in `xtask`) belongs to the tooling. It is here because this
   phase's insta snapshot showed the gap.
