# P2.3 — Service core: camera, display, stage and focus Things (`siq-server`, `apps/spectrumiq-server`) — implementation notes

- **Status:** Done (merged to `main` as `e4b9ecf`)
- **Branch / commits:** `phase/P2.3-server`, from `main` at `e52ac35`
- **Date:** 2026-10-24

## Summary

- **`siq-server`** (new, L5, the only crate on teta-wot):
  - **the device factory** (ADR-0034): from the configuration, each device simulated or real;
  - **the `Instrument` service:** the devices, the acquisition engine, the previews, the latest
    statistics and the metrics;
  - **four Things** (ADR-0033): `camera`, `display`, `stage` and `focus`, under `/api/v1/`, with the
    global lock on and `halt` bypassing it;
  - **SpectrumIQ's routes:** `/api/siq/system/health`, with teta-wot's router as the fallback
    (ADR-0003, amended);
  - **the lifecycle:** teta-wot's `serve_with` at v0.1.0, with live view and motion stopped
    before the Things.
- **`apps/spectrumiq-server`:** `[run] -c <config>`, `--print-openapi` and
  `--print-config-schema`.
- **`examples/python/live_and_move.py`** moves the stage, and saves an overview frame before and
  after. It needs only the standard library.
- **`siq-preview`'s settings and `siq-imgproc`'s `Colormap`** now derive serde and JSON Schema, so
  the display Thing serves them as they are.

## Interfaces

- **API:**
  - `siq_server::{Service, Instrument, openapi, shutdown_signal, API_PREFIX}`;
  - `siq_server::devices::{open, Devices}`;
  - the Thing types in `siq_server::things`.
- **HTTP:**
  - the Things' affordances are listed in ADR-0033 and the snapshot `server__things.snap`;
  - the OpenAPI paths are in `server__openapi_paths.snap`;
  - the health route is `/api/siq/system/health`.
- **For P2.4:** the peripheral Things and `imaging` join `things()`, with the peripherals in
  `Instrument`. The registry is `Instrument::registry`, for `/api/siq/system/metrics`.
- **For P3.x:** the client types come from `spectrumiq-server --print-openapi`.

## Deviations

1. **Two names differ from architecture §6.1** (ADR-0033):
   - the camera's sensor ROI is `region`, because `/camera/roi` is the ROI stream;
   - the stop actions are `halt`, because an action named `stop` collides with teta-wot's
     `Thing::stop`.
2. **The Python example uses the standard library,** not `httpx`. It runs without installing
   anything, so it could be run here.
3. **The display's `lut` and `roi_region` are the preview settings themselves,** serialized with
   serde. Their JSON is `{"contrast": {"kind": "auto", …}, "colormap": "grey"}` and
   `{"region": …, "zoom": "native"}`. The zoom is `native` or `half`, not 1 or 2.
4. **The OpenAPI and TD snapshots** cover the paths and each Thing's affordance names, not the
   whole documents. Those carry teta-wot's own wording, which a snapshot would pin.
5. **The frame pool is on the heap for the simulated camera,** and locked in RAM only for a real
   one.
