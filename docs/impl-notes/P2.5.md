# P2.5 — Euresys shim and bindings: risk spike (`siq-euresys-sys`) — implementation notes

- **Status:** Done (merged to `main` as `434f6b9`)
- **Branch / commits:** `phase/P2.5-euresys-shim`, from `main` at `681f311`
- **Date:** 2026-10-24

## Summary

- **`siq-euresys-sys`** (new, L2, raw FFI):
  - **`shim/siq_egrabber.h`:** a C ABI of plain types and opaque handles (ADR-0004, amended). It
    has 22 functions: discovery, opening a camera, features in four modules, user buffers,
    acquisition, pop and requeue, counters, and errors;
  - **`shim/siq_egrabber.cpp`:** the ABI over `EGrabber<CallbackOnDemand>`. Every entry point
    catches every exception and maps it to a status and a thread-local message;
  - **`build.rs`:** with the `sdk` feature, finds the SDK through `EGRABBER_SDK_DIR` and compiles
    the shim with MSVC (`/std:c++17 /EHsc`);
  - **`src/bindings.rs`:** the header's bindings, committed;
  - **the `eg_discover` example:** lists what a GenTL producer sees.
- **`cargo xtask regen-bindings`** regenerates the bindings with `bindgen-cli`, which needs
  libclang.
- **`cargo xtask ci`** now fails if a tracked file has an eGrabber SDK file's name
  (REQ-NFR-005).
- **`examples/python/live_soak.py`** runs live view with both previews streaming, and checks
  that no frame was lost. It checks M2's second exit criterion.

## Interfaces

- **API:** the header's functions and types, as `siq_euresys_sys::*`, and two helpers,
  `status_name` and, with `sdk`, `last_error`.
- **For P10.1 (`siq-euresys`, the safe `Camera`):**
  - wrap the system and the grabber in owners that close in order: the grabber before its
    system, and the pool's memory after the grabber;
  - announce the pool's slots with `siq_eg_announce_user_buffers`, in slot order. A buffer's
    index is then its slot;
  - pop on one thread, and stop it with `siq_eg_cancel_pop`;
  - map `SiqBufferInfo.timestamp` (ns, the grabber's clock) onto the `Clock`;
  - count `SiqEgCounters.underrun` as frames lost for want of a slot;
  - check `SiqBufferInfo.pixfmt_namespace` before reading `pixfmt` as PFNC.

## Deviations

1. **`bindings.rs` was written by hand, in bindgen's form,** not generated. libclang isn't
   installed, and installing LLVM was outside this phase.
   - `tests/layout.rs` binds it to the header: every struct's size and offsets (also
     `static_assert`ed in the C++), and every constant and function, by value and name.
   - Its first line says it was written by hand. The first `cargo xtask regen-bindings` should
     change only formatting and that line.
2. **The ABI has more than the brief's list:**
   - **a system handle** (`siq_eg_system_open`, `siq_eg_system_close`): the GenTL producer
     outlives its grabbers, and can be Playlink's;
   - **`siq_eg_discovery_info`:** gives discovery's strings;
   - **`siq_eg_cancel_pop`:** stops a pop waiting on another thread;
   - **`siq_eg_abi_version`:** checks that the shim and the bindings agree.
3. **`siq_eg_open` takes a camera from the discovery, not indexes.** `EGrabberDiscovery` takes
   exclusive control of the producer's device lists, and opening by index would fail.
4. **`SiqBufferInfo` has a tenth field, `pixfmt_namespace`.** Playlink's pixel format is a custom
   PFNC code, so the namespace is needed to read it. It fills what was padding, so the struct
   stays 64 bytes.
5. **The Playlink smoke test grabs, beyond discovery.** Playlink, from the SDK's installer, worked
   without hardware.

**By hand:**

- `cargo test -p siq-euresys-sys --features sdk -- --include-ignored` passes: 8 tests.
- `cargo build -p siq-euresys-sys --features sdk` succeeds with no warnings at `/W4`.
- `eg_discover` runs with both producers:
  - **with Coaxlink's (the default):** one interface, a Coaxlink Quad CXP-12 (`PC3603`), with an
    Adimec D-103A12c on it;
  - **with Playlink's:** one virtual camera.

  That is M2's third exit criterion.
- **`eg_discover --open` read the Adimec's features,** changing none:
  - 11264 × 9200, 103.6 MP;
  - `BayerGB8`;
  - 103,628,800 bytes a frame;
  - firmware `1.1.1-103773`.

  See the open question below.
- **Playlink's findings,** recorded in ADR-0004's amendment:
  - 720 × 720 `CustomJFIF` frames at 30 frames/s, with real ns timestamps;
  - frame ids always 0;
  - licence status "NotOK", which didn't stop acquisition.

**Unsafe review (ADR-0007):**
- `unsafe` is only in `siq-euresys-sys`, which ADR-0007 allows: the bindings' declarations, one
  block in `last_error`, and the example's and the `sdk` tests' calls.
- Each block has a `SAFETY` comment, saying what makes the pointers valid.
- The C++ checks every pointer for null before using it.

That is 5 new tests in a default build, in a workspace total of 219, and 4 more with `sdk`.
`cargo xtask ci` passes.

## Open questions

1. **The camera on this PC is a colour (Bayer) camera,** where the plan assumes mono.
   - REQ-ACQ-001 and the plan assume a ~100 MP 14-bit mono camera, in a Mono16 container.
     `config/sim.toml` simulates an 11648 × 8742 Mono14 sensor.
   - The Adimec D-103A12c connected here is 11264 × 9200. Its `c` and `BayerGB8` mean colour,
     and its name suggests 12 bits.
   - Is this the instrument's camera? If it is:
     - REQ-ACQ-001 and the simulator's sensor need changing;
     - P10.1 needs demosaicing, or must keep raw Bayer;
     - the previews, the stitching and 3D work on colour, or on one plane.

   This doesn't block M2. It is the plan's open question 1, now with facts.
