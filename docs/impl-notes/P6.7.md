# P6.7 — Run monitor and sequence UI — implementation notes

- **Status:** Done (merged to `main` as `c92662b`)
- **Branch / commits:** `phase/P6.7-run-monitor`, from `main` at `c72e0ce`
- **Date:** 2026-10-26

## Summary

- **The run panel** (ADR-0057, amended), below the Scan page's pane, for the run under way wherever
  it started:
  - its steps done, the time left and the step;
  - thumbnails of its latest eight frames, each the overview stream's next image after the frame
    is taken;
  - Pause or Resume, and Cancel once a dialog confirms it;
  - while a failed step waits, its error, with Retry and Skip;
  - once it ends, how it ended, until closed.
- **Recovery** (ADR-0052 and ADR-0056, amended): `ErrorPolicy.ask`. A failed step, once retried
  as often as it says, leaves the run waiting for `RunControl::decide`: Retry, Skip or Stop. The
  `workflow` Thing's `state` is then `asking`, with `problem`; its `retry` and `skip` actions
  decide, without the global lock. Every run takes `on_error`.
- **Notifications:** a toast as each run ends, from its `finished` event.
- **Sequences,** after `microscope`'s Sequence tab: the Scan page's second mode. Saved positions or
  where the stage is, channels, an autofocus and a z-stack at each, and a time-lapse; run as one
  plan through `workflow.run`.
- **`/#/dev/run`:** the page against a fake instrument whose runs take a step every half second,
  and wait, when asked, at their fourth.

## Interfaces

- **Public:**
  - `siq_workflow::engine::{ErrorPolicy::ask, Then::Ask, Decision, RunControl::decide}`;
  - `siq_server::workflow::{RunState::Asking, Problem}`; the Thing's `problem`, `retry` and
    `skip`, and `on_error` on every run;
  - web: `src/scan/{RunPanel, SequenceForm}.vue`, `src/scan/{sequence,thumbnails}.ts`; the
    workflow store's `problem`, `acquired`, `startPlan`, `cancel`, `pause`, `resume`, `retry`,
    `skip`; `notify` in `stores/thing.ts`.
- **For M7:** the live mosaic beside the run panel.
- **For M8:** stitching after a run, through the `DatasetHook` (P6.5).

## Deviations

1. **No run monitor page of its own:** the panel is on the Scan page, where runs start, and follows
   runs from scripts too. `/#/dev/run` is the example.
2. **Retry and skip choices are the `ask` policy's,** waiting on the failed step: after a run has
   failed, it would have to start again and find its place.
3. **Thumbnails from the overview stream, in the browser:** no server code. A frame taken before
   the stream shows the last goes without one.
4. **A sequence has no server estimate:** its frames are counted; the server checks the rest.
