# P3.5 — Tauri desktop shell — implementation notes

- **Status:** Done (merged to `main` as `09fe2d7`)
- **Branch / commits:** `phase/P3.5-desktop`, from `main` at `29a7bc4`
- **Date:** 2026-10-24

## Summary

- **`apps/spectrumiq-desktop`, the desktop shell** (ADR-0040). Tauri 2.12, with WebView2.
  - **`connect/`,** the bundled connect page:
    - it probes the service's health, then loads `http://127.0.0.1:<port>/`;
    - until then it says why and tries again every 2 s;
    - development builds offer to start the simulated instrument.
  - **`src-tauri/src/server.rs`:**
    - the service's address: `--server`, `SPECTRUMIQ_SERVER`, or 5000, on 127.0.0.1 only;
    - the health probe: one HTTP/1.1 request over loopback.
  - **`src-tauri/src/child.rs`,** in development builds only: `spectrumiq-server -c
    config/sim.toml` from the repository's `target/` (release, else debug), as a child process.
  - **`src-tauri/src/lib.rs`:**
    - the commands `app_info`, `probe`, `open_link`, `save_file` (raw body, name in a header),
      and in development builds `service_state`, `service_start`, `service_stop` and
      `service_restart`;
    - the single-instance, window-state, dialog and opener plugins;
    - the child killed on exit.
  - **`src-tauri/capabilities/`:**
    - `connect` for the bundled page;
    - `remote` for `http://127.0.0.1:*`: the host commands, the window's full screen and event
      listening, and nothing of Tauri's core set.
  - **`build.rs`** makes each command a permission (`tauri-build`'s app manifest).
  - **`icons/`** are rendered from the web app's favicon by `tauri icon`. Only the four that
    Windows needs are kept.
  - **`package.json`** holds Tauri's command line, for `npm run tauri dev`.
- **The web app:**
  - **`src/host/tauri.ts`,** the shell's `HostAdapter`:
    - `info` with kind `tauri`;
    - links through `open_link`;
    - files through `save_file`;
    - full screen through the window, followed through its resize events;
    - `service` where the shell manages one.
  - **`createHost`** (`src/host/index.ts`) picks it inside the shell, loading it as a chunk of its
    own. If the shell refuses, it falls back to the browser host.
  - **`main.ts`** mounts the app once the host is made.
  - **ESLint** keeps `@tauri-apps/*` inside `src/host/`.
- **The workspace:**
  - `apps/spectrumiq-desktop/src-tauri` is a member by name;
  - `apps/spectrumiq-desktop` is excluded, since the `apps/*` glob needs a manifest in each folder
    it matches.
- **Tauri's generated files** (`src-tauri/gen/`, `permissions/autogenerated/`) are ignored: each
  build writes them.

## Interfaces

- **`spectrumiq_desktop::server`:**
  - `DEFAULT_SERVER`, `HEALTH_PATH`;
  - `server_url(text)` and `configured(args, env)`, each returning `Url` or `UrlError`;
  - `probe(base, timeout)`, returning `Health` or `ProbeError`;
  - `spectrumiq_desktop::run()`.
- **The commands' JSON:** `app_info` returns `{ version, server, managesService }`;
  `service_state` returns `stopped`, `starting`, `running` or `failed`.
- **The web app:** `createHost(win)` and `createTauriHost()`. `AppInfo.kind` is `tauri` in the
  shell.

## Deviations

1. **"Service control" is the development server.** Production's Windows service arrives with
   P15.1, and its control with it.
2. **The connect page is plain HTML, CSS and a module script,** with no build step. Its colours
   copy the web app's accent rather than importing its tokens.
3. **The window's close isn't verified by hand.** It should stop the development server. The
   check needed a second scheduled task in the user's session, which was refused. Nothing else
   tests it, so it is left to the review.
4. **Not packaged:** `bundle.active` is false. The installer is P15.1's.

- **The web unit tests pass,** and so does `cargo xtask ci`.
- **By hand, on the desktop, with the development build.** The tool's shell runs in session 0,
  where WebView2 can't open a window, so a one-off scheduled task, since deleted, started the
  shell in the user's session. WebView2's DevTools protocol drove it:
  - the connect page said nothing answered at :5000, and offered the simulated instrument;
  - "Start the simulated instrument" started the release server, and the window loaded
    `http://127.0.0.1:5000/#/live`;
  - from that origin, `app_info` and `service_state` were allowed, and `probe` and
    `plugin:window|close` were refused, as the capabilities say;
  - `is_fullscreen` was allowed;
  - About said "Running in: The desktop app";
  - no console errors;
  - a second launch exited, leaving one shell.
- **`npm run tauri dev`** built and started the shell. From session 0 its window couldn't open,
  as with the direct launch.
