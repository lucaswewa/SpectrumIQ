# P1.9 — GRBL stage driver (`siq-grbl`) — implementation notes

- **Status:** Done (merged to `main` as `08b167b`)
- **Branch / commits:** `phase/P1.9-grbl-driver`, from `main` at `4129f50`
- **Date:** 2026-10-24

## Summary

- **`siq-grbl`** (new, L2): `GrblStage`, a `siq-devices` `Stage` for GRBL 1.1 and grblHAL, over
  any `LineTransport`.
- **A link task owns the transport.** It does the following:
  - sends one line at a time, and waits for its reply until a deadline on the clock;
  - sends realtime bytes and resets ahead of the lines;
  - polls `?` at `poll_hz`, and timestamps each report at its arrival less half the round trip;
  - drops late replies, and lines queued before a reset.
- **Connecting:** a reset and the banner, then `$$` (rates, accelerations, travel, homing seek;
  inches refused). Then re-sync: `$X` if locked and allowed, and `G21 G90`.
- **Moves:**
  - `G0`, or `G1 … F…`;
  - then `G4 P0`, within an allowance from the path;
  - then a fresh `Idle`;
  - optionally a backlash-consistent approach that overshoots by `[stage.motion]`.
- **Jogs, stop and homing:**
  - jogs with `$J=` to the edge of the travel, and 0x85;
  - `stop` holds, waits for `Hold:0`, resets and re-syncs;
  - `$H` sets `homed`;
  - the alarms that lose the position clear it.
- **Configuration:**
  - `[stage.motion]` holds `unlock`, `approach` and `overshoot`, for `kind = "grbl"` and `"sim"`;
  - they are validated: each approach is 1 or −1, and the overshoot is 0 or more.
- **The emulator's resets now match GRBL** (ADR-0027, amended):
  - a reset once held keeps the position;
  - a reset keeps the lock only if there was one.

## Interfaces

- **API:**
  - `siq_grbl::{GrblStage, GrblOptions}`, with `GrblStage::connect(transport, options, clock)`;
  - `siq_grbl::protocol::{State, Report, parse_status, parse_setting, error, loses_position}`;
  - `siq_config::model::GrblMotion`, in `SimStageConfig` and `GrblStageConfig` as `motion`.
- **For P2.3:**
  - for `[stage] kind = "grbl"`: `GrblStage::connect(siq_serial::open(port, …)?,
    GrblOptions::from(&grbl), clock)`;
  - for `kind = "sim"`: the same over `siq_serial::duplex`, with `GrblEmulator` serving the device
    end, and `GrblOptions::from(&sim_stage)`.
- **For P6.x scans:** `MoveOpts { approach: Approach::Unidirectional, .. }`.
- **For P10.3:** the `grbl_drive --port COMn [--move]` path.

## Deviations

1. **`AxisStatus` in the brief is `StageStatus` here,** P1.3's type for the three axes.
2. **`GrblStage` isn't generic over its transport,** as ADR-0027 sketched. The link task owns the
   transport, so only `connect` is generic, and the stage is one type behind `dyn Stage`.
3. **More than the brief, found while testing against the emulator and GRBL's documentation:**
   - late replies are dropped;
   - lines queued before a reset aren't sent;
   - `Hold:1` and `Door:2`/`Door:3` count as moving;
   - the `WCO` is kept between reports;
   - `$13=1` is refused;
   - the emulator's reset now behaves as GRBL's.
4. **The config's motion keys are validated,** which the brief didn't ask for.

- **The `driver` tests run the emulator** over a `DuplexTransport`, on a `ManualClock` that a task
  keeps at ten times real time. A scripted controller stands in for what the emulator doesn't do.
- **One flake was found and fixed in the test.** After a hold, the emulator's true stage lies
  between steps, while reports are whole steps printed to 1 µm. The tolerance is now 1 µm.
- **The `driver` binary passed 25 runs in a row.**
- **Manual, against a real controller:** `cargo run -p siq-grbl --example grbl_drive -- --port
  COMn`, and `--move` for 1 mm along −X and back. It wasn't run here: there is no board.

That is 16 new tests, all passing, in a workspace total of 164. `cargo xtask ci` passes.
