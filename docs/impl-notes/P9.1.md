# P9.1 — Accounts and sessions — implementation notes

- **Status:** Review
- **Branch / commits:** `phase/P9.1-accounts-sessions`, from `main` at `d2d583e`
- **Date:** 2026-10-27

## Summary

- **`siq-auth`** (new, L4; ADR-0065):
  - `UserStore`: the accounts in `users.json` in `[server] settings`, with argon2id hashes and a
    role each. It is read again when another process changes the file, and keeps the last admin.
  - `SessionStore`: sessions in memory, known by 256 random bits, ending when idle and when old.
  - `LoginLimiter`: failed logins counted per name, and per address at four times the limit.
  - `same_origin`, and the session cookie: `HttpOnly`, `SameSite=Strict`, `Path=/`.
  - `cli::run`: the `user` commands; `read_password`, without echo at a console.
- **`siq-server`:**
  - `POST /api/siq/auth/login` and `logout`, and `GET /api/siq/auth/me`;
  - a layer around every route, teta-wot's included, that refuses another site's changes with
    403, and gives a request with a live session's cookie its `Session`, its role read again;
  - the service served with each connection's address;
  - `Instrument::auth`.
- **`siq-config`'s `[auth]`:** `idle_minutes`, `session_hours`, `max_failures`, `failure_minutes`
  and `allowed_origins`.
- **`spectrumiq-server user add|passwd|role|list|remove`:** the first user is an admin.
- **`siq-auth --example user_cli`;** `test.http` gains the session requests.

## Interfaces

- **Public:** `siq_auth::{UserStore, User, Role, UserError, SessionStore, Session, SessionId,
  SessionPolicy, LoginLimiter, same_origin, set_cookie, session_cookie, clear_cookie,
  read_password, cli, USERS_FILE, MIN_PASSWORD}`; `siq_server::auth::Auth`, `Instrument::auth`;
  `siq_config::model::AuthConfig`.
- **HTTP:** the three session routes; a `403 {"detail"}` for another site's mutating request.
- **CLI:** `spectrumiq-server user …`.
- **For P9.2:** the layer's `Session` extension is the caller to authorize. The layer is where the
  route classification goes, and `siq-auth` hosts the local login's ACL module.

## Deviations

1. **No users routes yet:** architecture §6.2 places `/api/siq/users…` in P9.1, but until P9.2 can
   restrict them to admins they would let anyone manage the users. They come with the admin pages
   (P9.4); until then the CLI manages users.
2. **The users file is in `[server] settings`,** not `%ProgramData%\SpectrumIQ\config`: settings is
   where the service keeps what it is configured with (the calibrations, the flats). An installed
   service's settings will be under `%ProgramData%` (M15).
3. **The first admin is bootstrapped by the CLI:** the first `user add` makes an admin, and refuses
   another role. The service warns at start while there are no users. It makes no account by
   itself, so no default password ever exists.
4. **An address may fail four times as often as a name,** since a lab's shared computer serves
   many people; the brief named rate limiting only.
5. **`argon2` and `blake2` are optimised in dev builds:** unoptimised, a hash at the service's cost
   takes seconds, and the tests hash at that cost.
