# P1.2 — Frame fan-out (`siq-buffer::fanout`) — implementation notes

- **Status:** Review
- **Branch / commits:** `phase/P1.2-fanout`, from `main` at `f5a6acb`
- **Date:** 2026-10-23

## Summary

- **`Fanout`:** hands each published `FrameLease` to every subscriber whose filter takes it.
  - `publish(&lease)` clones the lease into each mailbox, an atomic increment each, and returns how
    many took it. It never waits for a consumer, and allocates nothing.
  - Clones share the fan-out. The last one dropped, or `close()`, closes it: subscribers read what
    is queued, then get `None`.
- **`subscribe(name, policy, filter)`** returns a `Subscriber`, with its own mailbox, allocated
  for its capacity:
  - `Policy::LatestOnly`: the newest frame replaces an unread one;
  - `Policy::Bounded { capacity, overflow }`: up to `capacity` frames, dropping the oldest or the
    newest when full;
  - `Policy::Lossless`: every frame. A slow lossless consumer keeps slots, so the pool runs dry
    and the producer loses frames. That is the backpressure (ADR-0022).
- **Receiving:** `try_recv`, `recv_blocking`, `recv_timeout`, and the future `recv()`, written on
  `std::task::Waker` for any executor. Dropping a subscriber unsubscribes it, and releases its
  queued frames.
- **`SubscriberStats`:** `received`, `dropped`, `taken`, `max_queued`, with
  `received = taken + dropped + queued`.
- **Locks:** the subscriber list's `RwLock`, and a mutex per mailbox, each held for constant work.
  No consumer code, waker or release sink runs under a mailbox lock.
- **No unsafe code, and no new dependency.**

## Interfaces

- **API:** `siq_buffer::{Fanout, Policy, Overflow, Subscriber, SubscriberStats, Recv, RecvError}`.
- **P2.1's acquisition engine:**
  - owns the `Fanout` for the camera's pool, and publishes each frame;
  - counts a dry pool as lost frames (REQ-ACQ-005);
  - reports each subscriber's statistics as metrics;
  - checks at start-up that the pool covers the subscribers: 2 slots per `LatestOnly`,
    `capacity + 1` per `Bounded`, plus the grabber's queue.
- **Consumers:**
  - previews and focus metrics subscribe `LatestOnly`;
  - live stitching subscribes `Bounded`;
  - the recorder subscribes `Lossless`, filtered on `flags.save`.
- **Release sinks** may now also run on the producer's thread, for frames a policy drops. A sink
  must not subscribe or unsubscribe.

## Deviations

1. **`Bounded { n, drop: Oldest | Newest }`** became `Bounded { capacity: NonZeroUsize, overflow:
   Overflow::DropOldest | DropNewest }`. An empty mailbox can't be asked for, and no field is called
   `drop`.
2. **"Max lag" is `max_queued`,** with `taken` beside it, so that the counts add up.
3. **`publish` returns** how many subscribers took the frame. A closed mailbox doesn't count.
4. **`recv_timeout` and `try_recv` were added** to `recv` and `recv_blocking`. Engines poll with a
   deadline, and the allocation test reads without waiting.
5. **The soak test runs a fixed 3000 frames,** not a timed run, so it is fast and its load is the
   same on every machine. The timed soak, at the camera's rate and frame size, is the
   `fanout_soak` example, whose smoke mode `cargo xtask ci` runs.
6. **Fan-out metrics in the registry are deferred to P2.1,** which names the subscribers (ADR-0022).
