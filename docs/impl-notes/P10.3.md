# P10.3 — Real stage and focus drive bring-up (on the emulators for now) — implementation notes

- **Status:** Review: a driver phase is Done once the owner has run its "How to try it" on the

- **Date:** 2026-10-29

## Summary

The owner kept the stage and the focus drive simulated (M10's amendment), so the bring-up was built
and checked on the emulators (ADR-0029 and ADR-0030, amended):

- **The controller's settings checked:**
  - `[stage.expect]` names the `$$` values a controller must have: steps/mm, rates,
    accelerations, travel, soft limits, homing;
  - a controller that differs is refused on connecting, every difference named;
  - `config/sim.toml` names the emulator's values.
- **The status's round trip** is kept for the reports that were polled: its count, least, mean
  and most. `grbl_drive` prints it, with `$$` as a `[stage.expect]` to copy.
- **The repeatability** is measured with the backlash in the stage–camera calibration, and kept in
  its record (`repeatability_um`): the standard deviation of a place's arrivals from one side. The
  new `motion_repeatability` example measures both over more repeats.
- **The serial ports are discovered:**
  - `siq_serial::ports()`;
  - `spectrumiq-server --list-ports`;
  - `GET /api/siq/system/ports`, with the device each is configured for and the configured ones
    missing;
  - the web app's first Settings page.
- **The runbook:** [`docs/hardware/motion-bringup.md`](../hardware/motion-bringup.md).

## Deviations

1. **On the emulators.** The owner's answer when M10 began: the stage and the focus drive stay
   simulated. The hardware tests of moves, repeatability, backlash and stops run against the GRBL
   emulator. Each step of the runbook is written for the real controller, with the emulator's
   numbers, until the owner runs them.
2. **The focus drive's dialect waits** for its vendor's protocol document, which the brief says
   the owner must provide. ADR-0030's amendment and the runbook's step 7 hold what follows it.
3. **The repeatability goes with the calibration,** into its record, rather than into a record of
   its own: it is measured from the same arrivals as the backlash, which the calibration already
   kept.
4. **The Settings page shows the ports, and changes nothing.** The configuration is a file the
   service reads at start. Editing it from the web app would be a feature of its own.
5. **A port seen on this PC wasn't opened.** `--list-ports` finds COM7, an FTDI USB serial
   adapter, perhaps the stage's or the focus drive's. The owner chose to keep both simulated, so
   nothing was sent to it.
6. **Fixed on the way:** the web README's `src/system/` row had a control character for its
   name.

## How to try it

1. `cargo run --release -p spectrumiq-server -- --list-ports`: this PC's ports. Then the web
   app's Settings page shows them, with what each is configured for.
2. `cargo run --release -p siq-grbl --example grbl_drive`: the emulator's session, and its round
   trip.
3. `cargo run --release -p siq-server --example motion_repeatability -- --repeats 20`: the
   repeatability and backlash against the injected noise and backlash.
4. In a copy of `config/sim.toml`, change `"$100"` under `[stage.expect]` to `800.0`, and start
   the service: it refuses, naming `$100`.
5. On the instrument, once the owner chooses to: the runbook, from its step 2.
