# P3.2 — API client: WebSocket observations, connection budget and stores — implementation notes

- **Status:** Review
- **Branch / commits:** `phase/P3.2-api-client`, from `main` at `aa0184b`
- **Date:** 2026-10-24

## Summary

- **Observations over WebSocket** (ADR-0037):
  - `ThingSocket` (`web/src/api/wot/ws.ts`) is one socket per Thing, over teta-wot's
    `{thing}/ws`, shared by every observation of that Thing;
  - it subscribes lazily, delivers values and events, and reports refusals;
  - it reconnects after 1 s, then up to 30 s, resubscribing to everything;
  - it closes with the last subscriber.
- **The client** uses a Thing's socket when its TD has one, and fetch-SSE otherwise.
  `webSocket: null` forces SSE. Requests carry `credentials: 'same-origin'` for M9's sessions.
- **`StreamBudget`** (`web/src/api/streams.ts`) runs at most 3 MJPEG streams:
  - a stream pauses while the page is hidden or its element is out of view, and resumes by
    itself;
  - it starts in the order asked, and never over the limit;
  - `useBudgetedStream` is the component-side helper, for P3.3.
- **The stores** (`web/src/stores/`):
  - **`connection`:** the TDs, health every 5 s, and lost and reconnecting states. It feeds the
    rail's availability and a connection indicator;
  - **`camera`, `display`, `stage`, `focus`, `imaging`, `peripherals`:** mirrors of their Things.
    Each value is read, then followed or polled. Actions run as invocations, and failures become
    toasts.
- **The API types:** `npm run api:openapi` and `api:types` write
  `src/api/generated/{openapi.json, schema.d.ts}`, which are committed.
  - The stores take their types from them, by name.
  - `cargo xtask ci` runs `api:types -- --check`.
  - A server test keeps `openapi.json` current.
- **The example:** `/#/dev/observe` shows every store's values, live, with buttons that move the
  stage and switch the channel.

## Deviations

1. **The copied SSE tests now test the fallback,** with `webSocket: null`. Their fake TDs have
   WebSocket forms, and happy-dom has a `WebSocket`.
2. **`useThingMirror` instead of `microscope`'s `TypedThing`:** a store-oriented helper, with the
   same typing from the OpenAPI schema names.
3. **The display's statistics are polled** (500 ms) and the camera's `stats` (1 s). They are
   functional properties, so teta-wot can't observe them.
4. **A server test,** `the_web_apps_openapi_document_is_current`, beyond the brief.
   `api:types -- --check` alone doesn't notice a stale `openapi.json`.
5. **The rail now hides destinations whose Things aren't served:** Mosaic, Scan, Datasets,
   Viewer, 3D, Jobs and Calibration, until their phases.
