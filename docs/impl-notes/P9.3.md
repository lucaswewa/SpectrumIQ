# P9.3 — Audit trail — implementation notes

- **Status:** Review
- **Branch / commits:** `phase/P9.3-audit-trail`, from `main` at `5d96753`
- **Date:** 2026-10-27

## Summary

- **`siq-auth::AuditLog`** (ADR-0067): JSON Lines, a file a month, `YYYY-MM.jsonl` in
  `[server] audit`.
  - Each line's `hash` is the SHA-256 of its own text without it, a text holding the line
    before's `hash` as `prev_hash`. A month's first line chains to the last month's last, across
    a restart too.
  - `record` doesn't wait: a thread of the trail's own numbers, chains and writes each entry,
    synced to disk, timed when it was recorded.
  - `query` filters by time, user and kind, newest first, in pages.
- **`audit::verify`** and **`spectrumiq-server audit verify`:** the first line edited, removed or
  moved, by file and line, and exit code 1; or the entries, files and last hash.
- **What is recorded:**
  - the logins, by password or the local secret, failed and refused ones, and the logouts;
  - the token's changes, by its keeper, with the holder before and after;
  - by the layer, every changing request (method, path, query, class, parameters, status) and
    every refusal;
  - every job's transitions (`siq-jobs`' new `Scheduler::on_transition`);
  - every workflow run's start and end;
  - every dataset deleted.
- **`GET /api/siq/audit`:** an admin's query.
- **`siq-auth --example audit_verify`;** `test.http` gains the queries.

## Interfaces

- **Public:** `siq_auth::{AuditLog, Event, Kind}`, `audit::{verify, Verified, Broken, Filter,
  Page, GENESIS}`, `ControlManager::with_audit`; `siq_jobs::Scheduler::on_transition`;
  `ServerConfig::audit`.
- **HTTP:** `GET /api/siq/audit?from&to&user&kind&offset&limit`, classed admin.
- **CLI:** `spectrumiq-server audit verify`.
- **For P9.4:** the audit viewer reads the query; `Kind` and `Filter` give its columns and
  filters.

## Deviations

1. **The token records its own changes, and the scheduler tells listeners:** fed from their
   `watch` channels as first written, the trail missed a token request and a quick job's end,
   since a watch keeps only the latest value. Every transition is recorded where it happens.
2. **Not every changing request is recorded:** the logins' own requests carry passwords and have
   their own entries; the token's heartbeat and the live mosaic's viewport change by the second
   and keep nothing.
3. **The hash covers the line as written,** not re-serialised JSON: a parser's choices can't change
   the bytes hashed.
4. **No rotation by size, and no deletion:** a month's file is kept; archiving is the lab's.
5. **The tests' and examples' services each write to a trail of their own,** in Cargo's target
   folder or a temporary one, not the repository's `audit/`, which `.gitignore` now lists.
